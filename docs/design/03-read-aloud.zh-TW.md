# 03 · 朗讀與聽力稽核（Read-aloud and listening audit）
[English](03-read-aloud.md) | **繁體中文**

> 把索引所用的同一份章節文字轉成語音，讓聆聽者聽到的就是檢索器看到的內容。原本是為英文聽力練習而做；稽核是附帶效果，現在則刻意加以運用。

## 1. 流程

```text
請求（依標題／關鍵字／隨機指定論文，或「下一段」）
  → 擷取模組（有快取）→ 選章節（預設：摘要；找不到時：第一個可朗讀的章節）
  → 取 ≤ 約 250 字，對齊句界；記住位置（論文、章節、段落、偏移）
  → 念法轉換（§2）                      # 只轉換語音用的版本
  → 語音合成（§3）→ OGG/Opus 語音訊息
  → 接著送：出處（標題、年份、章節、第幾段）→ 原文（隱藏／spoiler）→ 1–3 個詞彙
  → 選配：清楚標示為 AI 撰寫的補充說明，與論文內容分開
  → 聽者可回報問題 → 記錄下來，用於修正擷取規則（§4）
```

## 2. 念法轉換規則

依下列順序套用；每條規則都有單元測試（[05](05-acceptance-tests.zh-TW.md) §2）。

| 規則 | 範例 → 念法 |
|---|---|
| PDF 殘留瑕疵 | `measure-⏎ment`, `ﬁeld` → measurement, field |
| URL、DOI | 移除 |
| 數字編號引用 | `[12]`, `[3–5]`, `[1, 2]` → 移除 |
| 作者–年份引用 | `(Smith et al., 2023)`, `(Kim and Lee, 2019; Wang, 2020a)` → 移除 |
| 統計式（在方程式判斷之前處理） | `p < 0.05` → p less than zero point zero five；`R² = 0.87` → R squared equals …；`n = 30` → n equals thirty |
| 方程式 | 句中有 ≥ 4 個數學符號（`= + × ∑ ∫ ^ / < > ≤ ≥ { }`），且符號數多於 3 字母單字數 → 從音訊中刪去 |
| 縮寫 | 詞彙表：首次出現 → 念全稱，之後 → 念縮寫；若原文已寫成「full form (ABBR)」，則去掉括號；比對時英式／美式拼字視為相同 |
| 數字後的單位 | `25 °C` → twenty-five degrees Celsius；`1.5 dS/m` → … deciSiemens per meter；`200 µmol m⁻² s⁻¹` → … micromoles per square meter per second；`17 mol m-2 d-1` → … moles per square meter per day |
| 拉丁文縮寫 | e.g. → for example；i.e. → that is；vs. → versus |
| 希臘字母 | α → alpha、σ → sigma … |
| ± 與 = | plus or minus；equals |
| 百分比、年份、數字 | `15%` → fifteen percent；`2022` → twenty twenty-two；小數逐位念出 |

單位文法：數字後接一串單位記號，每個記號可帶指數（`^-2`、`-2`、上標 `⁻²`）或前置 `/`；負指數 → 「per」，指數絕對值為 2／3 → 「square／cubic」；第一個正指數單位用複數。

## 3. 語音合成

| 決策 | 選擇與理由 |
|---|---|
| 引擎 | Kokoro-82M，ONNX |
| 精度 | **fp32**：在我們的 ARM CPU 上 int8 慢了約 3 倍（合成 44 s 音訊：84 s 對 30 s） |
| 裝置 | **自動**：可用記憶體 ≥ 3,000 MB 時用 GPU，否則用 CPU；GPU 失敗時退回 CPU |
| 實測（44 s 音訊） | GPU：約 5 s，峰值約 2.1 GB · CPU：約 30 s，峰值約 0.9 GB |
| 並行 | 一次只做一個合成（檔案鎖） |
| 格式 | OGG/Opus 單聲道，由 libsndfile 直接寫出（不用 ffmpeg）；每分鐘約 260 KB |
| 聲音 | 語調富表情的美式英語（`af_bella`），供跟讀練習 |
| 語速 | 聽力 1.0 · 論文 0.9 · 跟讀 0.85 |

長文依句子邊界切成約 30–60 s 的片段；跟讀模式每則語音訊息一句（長句 > 22 字時，在最接近中間的逗號處切開）。

## 4. 聽力稽核紀錄

每筆聆聽回報記錄：時間、論文 id、章節、片段、聆聽者的描述，以及一個類別：

| 類別 | 常見原因 |
|---|---|
| 欄位混讀 | 閱讀順序 |
| 句子斷裂／黏連 | 區塊接合、斷字連字號 |
| 章節錯誤（例如把正文當摘要念） | 章節偵測 |
| 雜訊被念出（頁首、中繼資料、圖說） | 清理規則 |
| 亂碼 | 掃描／文字層 |
| 發音錯誤 | 念法轉換（不是索引問題） |

每項修正都會註明它解決了哪些回報；受影響的論文會重新擷取、重新建立索引，並用評測集量測修正前後的檢索效果。正是這份紀錄，能讓稽核從個案軼聞變成證據（見相關研究說明）。
